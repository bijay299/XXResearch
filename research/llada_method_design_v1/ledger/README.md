# Resource ledger

- `resources.jsonl`: one record per command run through `tools/ledger_run.py` (wall seconds, child user+sys CPU
  seconds, child max RSS, thread limit). These are **observed** values for the wrapped child process tree only.
- `manual.jsonl`: coordinator-entered records for work not run through the wrapper (installs, clones), with the
  measurement basis stated per record (`basis: observed|estimated|unmeasured`).
- Enforced limits: per-process BLAS/OpenMP thread caps set by the wrapper (default 1). There is **no** cgroup/CPU-quota
  enforcement and **no** cloud-billing telemetry; no dollar cap is claimed.
- Not captured: LLM-agent reasoning time (not CPU work on this host), editor/file operations, git operations.
- Machine: 4 vCPU, 15 GiB RAM, no GPU. Max possible CPU use over 8 h = 32 core-hours (< 48 core-hour ceiling).

## Totals at publication (see SUMMARY.md, generated by tools/ledger_summary.py)
- Observed CPU through the wrapper: see SUMMARY.md (≈ 5 core-hours), well under the 48 core-hour ceiling; the
  machine has 4 vCPU, so ≤ 32 core-hours were possible in 8 h.
- Memory: largest single wrapped process 2.7 GiB max RSS (pytest); typical runs 0.3–0.5 GiB; at most 4 concurrent
  run processes (≈ 2 GiB) plus agents' editors. No cgroup monitoring was available; the 16 GiB aggregate target was not
  approached on the evidence of per-process RSS (host total 15.7 GiB, never swapped — no swap configured).
- Storage added outside the repo: PyTorch env 1.6 GiB, micromamba package cache 0.7 GiB, pinned sources 0.17 GiB;
  sprint directory ≈ 62 MiB on disk (mostly git-ignored model snapshots). Total ≈ 2539 MiB (< 8 GiB).
- Failed wrapped runs: 2 (agent E: "counterexamples v1" and the first Prop2 check, each followed within a minute by a successful re-run of the corrected script; resources.jsonl).
- No GPUs, no model-weight downloads, no paid APIs. No dollar cap is claimed (no billing telemetry).
