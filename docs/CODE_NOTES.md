# CUIG code inspection notes

Source: CUIG @ `9932ac3271a122f6d38d19e0b8c8908fe5237ff7`. Findings that affect
how we launch, measure, or interpret the single-concept ConAbl baseline on
UnlearnCanvas.

---

## 1. Which script is the single-concept baseline

`BashScripts/Independent/Style/Base/ConAbl.sh`. Upstream's three settings are
`Independent` (unlearn one concept from the base model — the non-continual
baseline), `Sequential` (continue from the previous unlearned checkpoint via
`--unet_ckpt`), and `Simultaneous` (cumulative concept sets). "Independent" is
the right one for a single-concept baseline.

The script is a **submission generator**, not a job: it loops over 12 styles and
`sbatch`es one job per style. Running it unmodified would launch a full
12-concept sweep. Our launcher executes the generated job body for exactly one
style.

## 3. Anchor prompt count — a 1-off cliff

`anchor_prompts/style/Laion.txt` holds **exactly 200** non-empty lines. The file
has **no trailing newline**, so `wc -l` reports 199, which is misleading.

This matters because `_get_anchor_prompts_list` generates the shortfall via an
LLM when `len(prompts) < args.num_anchor_prompts`:

```python
openai.api_key = os.getenv("OPENAI_API_KEY")
openai.ChatCompletion.create(model="gpt-4.1", messages=llm_prompt)
```

At the released `--num_anchor_prompts 200` the branch is **not** taken, so the
baseline runs with no API key — confirmed. Anything above 200 would fire a live
OpenAI call and fail here (no key is set, and we do not intend to set one).
`openai` is nonetheless a hard top-level import in `ConAbl/src/data.py`, so the
package must be installed regardless.

## 4. How the loss is actually computed (style, no anchor preservation)

The released independent-style script does **not** pass
`--with_anchor_preservation`, so the objective reduces to the ablation term
alone (`train_conabl.py` L213-228):

1. encode an **anchor** image to latents, add noise at a random timestep;
2. predict noise conditioned on the **target** prompt (gradients on);
3. predict noise conditioned on the **anchor** prompt under `no_grad` — the
   stop-gradient teacher;
4. MSE between the two predictions, masked to the valid (unpadded) image region,
   normalised per valid pixel, averaged over the batch.

So the target concept is pulled onto the anchor concept's prediction; there is
no ground-truth-noise term. Only `attn2.to_k` / `attn2.to_v` are trainable
(`--parameter_group kv-xattn`, the default).

Target prompts for styles are built in `AnchorDataset.__getprompt__`: the style
is randomly **prepended** (`"In {Style} Style, {caption}"`) or **appended**
(`"{caption}, in {Style} Style."`) to each anchor caption, since
`--with_style_replacement` is off. `setup_concepts_list` maps
`Abstractionism` → target concept string `"Abstractionism Style"`.

## 5. Checkpoint format

`CustomDiffusionPipeline.save_pretrained(..., all=False)` writes
`<output_dir>/delta.bin` as `{"unet": {param_name: tensor}}` containing **only**
`attn2.to_k` / `attn2.to_v` — 32 tensors, 19,169,280 parameters for SD-1.x.
`sample.py::normalize_unet_state_dict` strips a `unet.` prefix and unwraps the
`"unet"` key, then loads with `strict=False`. Verified empirically: 0 unexpected
keys, 654 missing keys (expected — the rest of the UNet keeps base weights).

## 6. Evaluation and the label-agreement question

`evaluate.py` turns a concept name into an integer with
`STYLES_AVAILABLE.index(name)` / `OBJECTS_AVAILABLE.index(name)` and maps
predictions back with `STYLES_AVAILABLE[pred]`. Correct metrics therefore
require the classifier's output ordering to match those lists exactly.

Established statically: `STYLES_AVAILABLE` has 51 entries (50 styles +
`Seed_Images`) and `OBJECTS_AVAILABLE` has 20, **both exactly alphabetically
sorted**, index 0 being `Abstractionism` / `Architectures`. That is consistent
with `ImageFolder`-derived class ordering, and `evaluate.py` builds the head as
`Linear(1024, len(...))`, so a wrong class count fails loudly.

**Not established without the checkpoints:** that the classifiers were trained
in that order. A silent permutation would corrupt UA/IRA/CRA without error. The
empirical check is in `docs/ASSETS.md` §6 — sample from the unmodified generator
and confirm high top-1; near-chance accuracy on a healthy generator indicates a
permuted ordering.

Metric definitions (`compute_unlearncanvas_summary`): `UA = 100 − acc(target)`,
`IRA = mean acc(in-domain retain)`, `CRA = mean acc(cross-domain retain)`. For
style unlearning the style classifier is primary and the object classifier is
secondary.

## 7. `evaluate.py` requires an `images/` path segment

`_record_prediction` (L240):

```python
short_img_path = os.path.splitext(img_path.split("images/")[1])[0]
```

If `--input_dir` contains no `images/` segment this raises `IndexError` on the
first scored image. Upstream satisfies it incidentally through its
`Results/<target>/images` layout. Our launchers keep that layout deliberately
and comment the requirement, so a future refactor doesn't silently break
evaluation.

A second quirk: missing images are **skipped with a warning**, not an error, so
an interrupted sampling run still yields a `summary.json` computed over fewer
images. For reporting, verify the image count equals
`styles × objects × seeds` before trusting a summary.

## 8. Device selection hazard in the accelerate config

Upstream `Configs/Accelerator/single_gpu.yaml` sets `gpu_ids: '0'`, which makes
`accelerate launch` **overwrite** `CUDA_VISIBLE_DEVICES` in the child process.
On a shared host this silently relocates the job to physical GPU 0. Verified,
and worked around in `configs/accelerate_single_visible_gpu.yaml`
(`gpu_ids: all`); full detail in `docs/DEVIATIONS.md` §2.

`sample.py` and `evaluate.py` default to `--device cuda:0`, i.e. the first
*visible* device, which is correct under our single-device pin.

## 9. Cost model for the full baseline (estimates, not measurements)

From the measured substitute run (A100-40GB, GPU 2): anchor generation ran at
≈6.8 s per batch of 4 images at 100 steps, and sampling at ≈7 s/image at 100
steps with CFG 9.0.

| Stage | Work at released settings | Rough estimate |
|---|---|---|
| Anchor generation | 200 images, 100 steps, batch 4 | ~6 min |
| Training | 1000 optimizer steps, batch 4, fp32, kv-xattn | ~20–30 min |
| Sampling | 13 styles × 8 objects × 5 seeds = 520 images | ~45–60 min |
| Evaluation | 1040 ViT-L forwards | ~3–5 min |

Peak GPU memory for the substitute training configuration was **11,156 MiB**,
comfortably inside 40 GB; the released configuration differs only in step count
and anchor count, not in batch size or precision, so memory should be similar.
These are projections — the baseline has not been run.
